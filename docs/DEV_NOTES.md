# Overreact: notes for whoever works on the code

Read this before changing anything. Then read `EVALUATOR_BRIEF.md`, `ARC.md`, `EVALUATION.md`, `BALANCE.md`, `ENGINES.md` and `PASS.md`.

## Hard rules

- Work only in `C:\Work\atlas-atoms` on branch `steam`. Never commit to `main`. Never touch the deployed site.
- Commit with `git -c user.name="m-g-mccoyiii" -c user.email="m.g.mccoyiii@gmail.com" commit`. Do not change git config. End every commit message with `Co-Authored-By: Claude <noreply@anthropic.com>`. Push to `origin steam` after every commit.
- Do not download any file. Everything shipped must be licensed for commercial use.
- Vanilla JS globals on `AA`, Three.js r128, Canvas 2D, Web Audio, localStorage. No node, no build step. The page has a CSP that forbids inline scripts.
- Any edited script or css needs its `?v=N` bumped in both `apps/steam/scheme.html` and `.claude/rec.html`.
- American spelling.

## The owner's taste, which decides what passes

- A fun, insane, fast game. Not textbook-like. Not like cheap mobile game ads.
- Words on a game screen are names, numbers and short tokens. No sentences. Only instructions may be wordy. No quips, no ominous hints, no second-person labels.
- No multiplication signs, middle dots or em dashes in text.
- UI is objects. Menus are full game screens, never a dialog with titled boxes.
- Rejected looks: dark navy, uppercase letter-spaced mono labels, serif headings, glow accents, flat signage, hard rectangles, cards like Balatro's, yellow pills and banners added for excitement, pulsing buttons, bursts, particle balls, check marks.
- Do not restyle the ball-and-stick molecule. Never put faces on atoms.
- Every new layer is unlocked by play. Nothing later than the player's stage is shown.
- No timers, login streaks or paid currency. No daily challenge.

## How to change code safely

These files have very long lines. Do not rewrite them. Write a small Python script with the Write tool into the scratchpad that does exact-string replacement with a count assertion, then run it:

```python
def rep(s, a, b):
    assert s.count(a) == 1, (a[:70], s.count(a)); return s.replace(a, b)
```

Heredocs with nested quotes fail in this shell; a script file does not.

## How to see the game

- A preview server serves the repo at `http://localhost:8766`. The game is `/apps/steam/scheme.html`. The recording page is `/.claude/rec.html?name=none&r=<any number>`.
- A frame server on port 8767 saves POSTed frames as `fNNNNN.jpg` into the scratchpad `frames` folder. If nothing is listening there, start `recsrv.py` from the scratchpad in the background.
- In the recording page: `await recClip(base, '', {feed, kit, rack, by, term}, n)` plays n reactions and saves every frame from number `base`; `recStill`, `recTick(ms, {base, label, i})`. `window.__fast = true` speeds the player. `window.__nopost = true` runs without saving frames.
- Resize the browser to 1280 by 720 before recording and only reset it after the recording has finished.
- The browser's JavaScript tool times out near 45 seconds. For long work, do it in chunks of about 22 seconds, one call per chunk. Background timers in the pane are throttled to about one a minute, so never rely on `setTimeout` loops for long jobs.
- `AA.rxScheme.debugStage(n)`, `debugTerm(i)`, `debugKit(ids)`, `debugRack(ids)`, `debugFeed(smiles)` set up a state. `AA.rxScheme.meta` is the saved progress.
- To measure: `AA.rxPath.synPlay(feed, rnd, gear, run, 'greedy')` plays one round and returns the total. Pass a seeded `rnd` so two measurements see the same deals. `docs/MATRIX.md` was made this way; the script that builds it is `matrix.py` in the scratchpad.
- To measure whole runs: `runSim(player, seed, opts)` and the rest of the rig, in `.claude/sim.js` (copy in `docs/tools_sim.js`). `docs/RIG.md` says how. `opts.rule` overrides `AA.rxPath.RULE` for one run, so a rule can be measured on and off on the same seeds; `opts.dec` logs how much of a choice each turn was. `python docs/tools_round.py <tag> <first> <last>` prints the spread of a round and the turn measures.
- Never start `simGo` or `simPart` in a tab where one is still running: the two fight over one job and neither ends. Reload the tab first.
- `AA.rxScheme.bank()`, `redraw()` and `turn()` do what the three new marks do. `state()` reports `fork`, `canBank`, `canRedraw`, `stuck` and `left`. `AA.rxPath.seed(n)` seeds every draw on the run path; `AA.rxScheme.debugRound(n)` jumps the page to a round.
- The page is lined up and fired: `AA.rxScheme.pick(i)` places slot i of the hand in the next circle, `unqueue(k)` takes circle k back (-1 for the last), `bank()` places the bank token, `fire()` fires. `state()` reports `queue`, `will` (what each queued thing will do), `lining`, `casc`, `coins`. On the take-one page `reroll()`, `skip()`, `bin(i)`. `recQ(base, opts, pages, plan)` in the recording page records pages lined up and fired. Never take a screenshot of the recording page: it runs the page's own clock against the recording clock and the view breaks.
- Judge whole frames, not crops. Look at what you built before saying it works.
- **To design a molecule or a reagent, do not play runs.** `AA.rxPath.screen(smiles, pool, kinds)` works a cascade out from the structure alone in about 25 ms: the steps as dealt, the best line of three, the best from every deal of five. `screenRound(smiles, pool, kinds, rnd)` plays three pages. In the recording page `scrTable(pool, kinds, n, ms)` runs every molecule as rounds deal them and prints the share of pages with 1, 3, 6 and 10 steps; call it again until it stops answering `left`. `cascBox(list)` gives the steps as dealt for a list of `[family, smiles]`. Whole runs are for the number to beat and the pass-rate table only. `python docs/tools_casc.py <tag> <first> <last>` prints the cascade lengths in a measure.
- The bare game is measured with `{ all: true, tier: 0, rule: { bare: true, co2: false } }` (`RIG.md`, first section). Its Par comes from `python docs/tools_par_bare.py <tag> <first> <last> par.json 4 1.05`, then `tools_bake.py par.json -`. With `tier: 0` 500 runs for each player take about 15 minutes over nine tabs; with all suppliers open the players' reading of the pair of molecules makes a run of the greedy player take 10 seconds. `simPart` splits the work unevenly for this: start `simGo` by hand in each tab with a range of seeds and its own file base.
- A measure of 500 runs for each of the four players takes about 25 minutes over eight tabs now: the median player tries every line of the hand. Keep the tab you are looking at idle while it runs.
- Pieces are used on the molecule (`PIECES.md`): `AA.rxScheme.toolArm(id)` picks one up, `st.toolList` holds the places, `toolPeek(i)` shows one, `toolUse(i)` uses it. `AA.rxPath.toolSpots`, `toolUse`, `toolGo`, `toolWorth`, `toolBest` are the rules; `RULE.five = false` brings all sixty old pieces back. The five are mirror, seed crystal, magnet, burner and burette; `AA.rxPath.fifthSet('balance')` or `'mortar'` swaps the fifth for a candidate that was built and not chosen. A piece that drives something off returns it as `leaving` and the page flies it away (`g.reopened.gone`, `flyer` in scheme.js). In the recording page `recTool(base, feed, kit, id)` records one piece used at its best place, `toolTable(mols, sets)` reads pieces off the structure (steps as dealt), `toolLine(mols, sets)` starts a job that reads the best line of three reagents after the pieces (`lineStat`, `lineRows`), `toolRound` plays a round with them. A real click on a piece must land on its foot or its name, not its top. The simulated players use pieces through `useTools(g, rnd, mode, only, pageOf)` in `sim.js` (modes `read`, `plan`, `best`, `random`); `SIM.toolStat` counts what was held, proposed, dropped and used. In `toolRound(smi, seed, gear, how)` pass `'read'` or `'random'`, and compare with the same gear and no `how`, not with no gear.
- Layout is checked by number, not by eye alone: `AA.rxScheme.debugShape(smiles, { tool, spot, zips, show })` lays a molecule out (after a piece or some zip steps if asked) and returns the worst bond length over the normal one (`worst`), the nearest two atoms that are not bonded (`near`, in bond lengths), the box (`w`, `d`), the box before it turned back (`uw`, `ud`), the radius of the turn (`fr`, 0 when straight) and the scale (`sc`). Sweep every molecule in `AA.rxPath.FEEDS` with it after touching `tidy`, `closeRings` or the turn. `toolWorths()` gives what each place of the piece picked up is worth, `toolGhost()` the mirror's ghost, `debugMorph()` the move being played.
- On the page the go arrow sits after the last circle, so it moves when a piece of equipment adds a circle. Read where it is from a screenshot before clicking it.
- Jars and homunculi (`JARS.md`): `AA.rxPath.JAR` (fill counts, stages), `HOMS` (one table entry per homunculus: `feed`, `need`, `spots(m)`, `act(m, spot)`), `homReady`, `homSpots`, `homTry`, `homUse`, `homGo`, `runBank`; `run.hom` is the one taken into a run and `g.hom` is `{ id, fed, used }`. On the page: `AA.rxScheme.debugJar({ water, h2 })` sets the jars (a full one hatches), `debugHom('water' | 'h2' | null)` takes one into the run and deals the round again, `debugFeedHom(n)` feeds it outright, `homState()` reports it, `homUse(i)` sets it off at place i while the page waits, `homSkip()` turns the page, `showHoms()` and `chooseHom(i)` are the page before a run. Saved progress has `jar` and `hatched`. Debug calls that save (`debugJar`, `debugStage`) write the owner's saved progress: copy `localStorage.aa_scheme_meta` first and put it back. In the recording page `recHom(base, { hom, feed, rack, kit, tool, fed, line, spot, round })` records one being set off, `homRound(smiles, seed, hom, how)` plays a round with one and `homTable(mols, cfgs, seeds)` is the job; `runSim(player, seed, { hom })` takes one into a run.
- The ten homunculi (`HOMUNCULI.md`) are one table, `AA.rxPath.HOMS`: `name`, `tok`, `jar` (fast, medium, slow), `feed` (a list of events: `water`, `h2`, `co2` for what leaves, `use:<reagent id>` for a reagent that acted; raise any other with `homEvent(g, key)`), `need`, `uses` (taps a round), `whole`, `word` (lettered in the preview), `spots(m, g)`, `act(m, spot, g)` (returns `made`, and `restart` or `frozen`), `now(g)` (a rule of thumb for the simulated players when its worth is not steps), `pay` (dry ice), `offered: false` for one not built. To add one: fill its entry in `HOMS`; give it a count in `JAR.full`; a figure `hom<id>` in `kitart.js` and its id, color and ink in `JARC`, `JARINK`, `HOMID` in `scheme.js`; nothing else (the jar row, the page before a run, `runBank`, `debugJar`, `runSim(..., { hom })` and `SIM.useHom` all read the table). `homFed(g)` is fed and not used up; `homLit(g)` is fed with somewhere to act; `g.hom` is `{ id, fed, used, frozen }`. `frozenPay(g)` pays frozen rings when a page turns. A frozen ring's oxygen carries `frz` and `RX.reopen` leaves it shut. `RULE.co2` is on: oxidize cuts an end C=C and carbon dioxide leaves. In the rig a player that reads decides the freeze by playing the rest of the round both ways (`ahead` in `playRound`). A measure with and without a creature: `simGo('tag', ['median'], 1, 100, base, { all: true, hom: 'co2' })` in one tab and the same without `hom` in another, then `python docs/tools_hom_cmp.py <base of none> <base of creature>`.
- Choosing the molecule (`LOOP.md`): `RULE.choose` (on). `runBriefs(run)` then returns two molecules (one in a first run, `run.single`), each with `ease` (`easeOf(run, smiles)`: the screen's best cascade from a hand of five, averaged over hands, plus the share of lines that set off any) and `coins` (the harder one pays 1 when `CHOOSE.one` behind, 2 when `CHOOSE.two`). `runChoose` keeps the coins in `run.payCoins` and `runEarn` pays them when the round is beaten (`extra`). `pairCost(run)` is 1, 2, 3 then nothing; `runRedraw(run)` pays it and deals again. On the page: `AA.rxScheme.chooseBrief(i)`, `redrawPair()`, `debugCoins(n)`, `debugCoined(true)` (the redraw mark shows only once a coin has been held, saved as `coined`); `state()` on that page has `pair`, `pairCost`, `pairX`, `pairAt`. Rig: the players have `pair` (`net`, `ease`, or random); the round log has `coins0`, `pairCoins`, `pairGap`, `redrew`. With `RULE.choose` off the three kinds of round come back.
- A source of carbon dioxide, for measuring: `RULE.co2` (off). Oxidize then also cuts a C=C at the very end of a chain; the end carbon leaves as `co2` (`byKind`), counted in `g.by.co2` and the round log. The screen reads `AA.rx.MODE.co2` directly: set it yourself around `screen` or `scrTable`. Numbers in `HOMUNCULI_2.md`.
- A whole frame of the page as it stands, without the recording clock (for frames taken after real clicks, in the recording page only): stub `requestAnimationFrame`, call `AA.rxScheme.frame(performance.now())`, draw the canvas into a 1280 by 720 canvas and post it to the frame server in the same call. A `requestAnimationFrame` callback does not run while the pane is hidden.
- **The bare game** (docs/ORDER.md, layers 1 to 4): `AA.rxPath.RULE.bare = true` offers and holds no piece and takes no creature; `AA.rxScheme.debugBare(true)` sets it and starts a new run; `runSim(player, seed, { rule: { bare: true } })` measures it. It is off by default, so real play is unchanged. In the bare game the jars are not drawn and what leaves the molecule flies off the top left of the page. With no piece on the page and no creature the molecule takes the whole middle (`laneSet`, `LANE` in scheme.js).
- The round page: the number to beat is a red flag on a track (`TRK`, `flag()`), the total runs along the track as a line of ink, the marks are the smaller flags past it with the coin each pays. The two numbers that multiply are one small handwritten line under the total (`FORM`). The same flag stands by each number on the pair page.
- Real clicks in the recording page: set `window.requestAnimationFrame = () => 0` and take one small screenshot BEFORE the first `recTick` (the click tool needs a screenshot to know the frame; a screenshot after the recording clock has started breaks the ink). Screenshot coordinates are 800 by 450: a page point (x, z) is found by projecting with a camera at (0, 43, 22.6) looking at (0, 0, 0.6), field of view 34.

- **Tiers and tier one (2026-11-11, `RIG.md` fifth measure).** `P.runNew(tier, extra, { tierNo: 1 | 2 | 3 })` makes a run of 3, 6 or 9 rounds (`run.span`, `P.runLast(run)`, `P.runWon(run)`, `P.TIERS`, `P.tierRule(n)`); tier 1 sets `run.bare` and `run.six`. The first argument is still the supplier index, an older thing also called tier. `runSim(player, seed, { tierNo: 1, tier: 0, all: true, rule: { co2: false } })` is a tier-one run. Switches: `RULE.next` (the next hand, `g.nextHand`), `RULE.lastx` (what the molecule does after the third reaction pays double; `g.lastOn`, event field `lastx`), `RULE.filter` (`P.feedShape`). `P.queueSwap(g, i, j)`, `P.queueMove(g, from, to)`, `P.fitsNow(g, id)`, `P.queueFits(g)`, `P.usesBind()`. `python docs/tools_tier1.py <tag> <first> <last> fit 4,3,3 [par.json]` (or `baked`) prints the tier-one tables; `python docs/tools_tier1_bake.py <factors.json or -> <par.json or ->` writes the molecule factors and the first three numbers into `path.js` and leaves the rest. `lineStudy(from, to, rule)` and `lineSum` (defined by hand in the recording page, see `RIG.md`) play every ordered line of a page.
- The coin sink (`RULE.sink`, off): `P.SINK.price` (1, 2, 3 within a round), `P.useCost(g)` (the price of the next use, or undefined when the switch is off or no more can be bought this round), `P.canBuyUse(g, run, id)`, `P.buyUse(g, run, id)` (takes the coins from `run.coins`, adds one to `g.left[id]`, counts `g.bought`). ## Measuring, since 2026-11-11 (the sixth measure in `RIG.md`)

- **Measure headless, not in the browser pane** (`HEADLESS.md`). `.claude/headless/hlmany.sh <tag> <player> <from> <n> <pages> <timeout s> '<opts json>'` runs a measure over several pages at once (job `jobs/simR.js`, every round row of the rig); `python docs/tools_hl.py gather <tag> <base>` puts the results where `tools_rig.py`, `tools_tier1.py` and the others read them. Start at most six pages together: the static server on 8766 answers one request at a time and a page can lose a script (the script runs such a page again). Tier one, 500 runs for each of four players, takes under two minutes.
- **The leak.** Until commit 4a11ef4 the reaction modes (`AA.rx.MODE`, most of all `co2`) were set only when a round began, so the pair of molecules of a run was read under what the run before had left, and `easeOf` kept readings made under one mode for the other. `P.modeSync(run)` now sets the modes whenever rules are read for a run, and `runSim` puts `P.RULE` and `AA.rx.MODE` back in a `finally`. Never trust a number made before that fix with `co2` switched on and off in one tab without running it again. Measures that passed `co2: false` throughout (the fourth and fifth) were not touched.
- A bare run (`RULE.bare` or tier 1) gives off no carbon dioxide whatever `RULE.co2` says.
- Any code that sets a rule for a measure must put it back in a `finally`, and must call `P.modeSync(run)` if it reads the screen outside a round.
- A table read on 300 runs gives each molecule 8 to 20 plays in a round: the spread of molecules needs 2,000 runs or more.

## What is known to be wrong

See `EVALUATION.md` and `RIG.md` ("What is still wrong, found in this measure"). In short: a round is bounded now (32 heavy atoms, a chain of six, two loops, three uses a reagent) and its spread is 9 to 34 times where it was hundreds, but 59% of passed rounds are still passed by more than five times and the last page decides 28%; molecules in the same round differ by 3 to 8 times; kinds of round differ by 9 times and a scarce round is far the hardest; a turn has a second option worth taking in 53% of the median player's turns, which is just over the gate; the bank wins on seven builds in ten and may be too good; levels on multiplying pieces make the top of late rounds; the worth tables the simulated players pick by are stale; two thirds of piece pairs do not interact; twelve pieces are dead and seven harmful (measured under the old rules); the overreact chain is not a spectacle; the page has rejected looks (navy ink, yellow pills), and product thumbnails at the right edge can be cut by the frame.
- Eight homunculi are built (acid, wood spirit, salt, slime, seedling added). New table fields: `before` (tapped before the line: `AA.rxScheme.homTap()` does the click on the figure, then `homUse(i)` for a place), `lasting`, and `act` may return `over` and `line`. `AA.rx.homs` holds what they do to the graph. `runSim(player, seed, { hom, homFed: true })` starts every round fed; `window.__forcePre = true` makes a player tap a before-the-line creature whenever it is lit. `debugShape(smiles, { hom, spot, zips })` lays a molecule out after a creature. In the recording page `recHomPre(base, { hom, feed, rack, line })` records a tap before the line.
- `P.swapQueue(i, j)` swaps two queued circles before firing. `P.RULE.usesFree` (on) makes uses never run out in the three-round bare run; `P.usesFreeOn(run)` tells the page to hide the use marks.
